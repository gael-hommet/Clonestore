## Détail des issues P0/P1 (reproduction et impact)

### ISSUE-01 — P0 → **FERMÉ 2026-07-23, RÉGRESSÉ SILENCIEUSEMENT, RE-FERMÉ 2026-07-24 (P0.1 re-closure)** — Floor "email jamais auto-exécuté" non universel
- **Reproduction (avant correctif initial)** : lecture de `src/app/api/pierre/execute/route.ts` (551 lignes) ; grep `cloneguard|governance|requires_human|approval` → 0 résultat.
- **Correctif du 2026-07-23** : la route appelait `evaluateLegacyExecuteGovernance` (nouveau module `src/lib/pierre/legacy-execute-governance.ts`) avant toute exécution ; tout appel direct à Make.com avait été retiré du fichier. **Ce correctif n'a jamais été commité en Git et a été écrasé sur disque le 2026-07-24** par un chantier externe concurrent de refactor lazy-init — voir ISSUE-40 et `P0_1_GIT_FORENSIC_TIMELINE.md` pour la preuve forensique complète (classification `GOVERNED_VERSION_EXISTED_AND_WAS_OVERWRITTEN`).
- **Re-correctif du 2026-07-24 (bloc P0.1 re-closure)** : gouvernance réintégrée à l'identique dans `route.ts` (même module, aucun second évaluateur), connecteur Make direct retiré entièrement cette fois (pas seulement contourné) ; `hris.sync` reçoit en plus un plancher route dédié (jamais ALLOW, même si le moteur se trompait).
- **Vérifié (2026-07-24)** : 18 tests réels (8 unitaires + 10 intégration) prouvent que les 3 actions résultent en `DENY`/`REQUIRE_APPROVAL` et qu'aucun appel réseau externe n'est jamais déclenché. 5611/5613 tests de la zone Pierre + 9165/9165 `npm test` toujours verts (voir `P0_1_TEST_MATRIX.md` pour le détail sans double comptage).
- **Risque résiduel** : `/api/pierre/action`/`/api/router` (P0.2, ISSUE-38/39) restent fermés et cohérents (tests transversaux 15/15) ; `run/route.ts` hérite de la protection d'`execute` sans logique propre (R1, `P0_1_REMAINING_RISKS.md`).
- **Impact business** : contradiction directe de la promesse de confiance/gouvernance vendue au client (449€/mois) tant que la route restait ouverte — désormais neutralisée côté code, avec un mécanisme de re-vérification renforcé (voir R5 dans `P0_1_REMAINING_RISKS.md` sur le risque de perte répétée tant qu'aucun commit Git réel n'existe).

### ISSUE-02 — P1 — CTA d'achat mort (tarif pays)
- **Reproduction** : `src/components/pricing/CountryPricingCard.tsx:119-127` — bouton sans prop `onClick`. Confirmé sur la page réelle `/agents/pierre` (desktop 1440, capture à l'appui).
- **Device** : desktop confirmé ; mobile non re-testé séparément mais le bug est dans le JS du composant, donc probablement identique.
- **Reproduction pas-à-pas** : aller sur `/agents/pierre` → section "Tarif par pays" → sélectionner "Suisse" → le prix 499 CHF/mois s'affiche, le bouton est actif (non grisé) → cliquer → rien ne se passe, aucune navigation, aucune erreur visible.
- **Impact utilisateur** : un prospect suisse intéressé et prêt à acheter est bloqué sans message d'erreur à l'étape la plus proche de la conversion.
- **Impact business** : perte de conversion directe et silencieuse sur un marché ciblé (Suisse, 499 CHF/mois). Aucun test automatisé ne couvre ce composant.
- **Recommandation générale** : câbler le `onClick` vers `/checkout` (ou `/api/checkout`) en propageant le pays sélectionné.

### ISSUE-03 — P1 — 500 reproduit sur `/paiement`
- **Reproduction** : navigation Playwright répétée vers `http://localhost:3000/paiement`. Log serveur : `⨯ SyntaxError: Unexpected end of JSON input ... page: '/paiement'` → `GET /paiement 500 in 37712ms`, suivi d'un retour à 200 au rechargement suivant.
- **Device** : desktop, environnement dev local.
- **Impact utilisateur** : un visiteur peut atterrir sur une page d'erreur générique au moment précis du paiement.
- **Confiance** : élevée sur la reproduction en dev ; **non confirmée en production buildée** (le comportement pourrait être lié à une race condition spécifique au mode compilation-à-la-demande de `next dev`) — recommandé de re-tester après un build de production stable.
- **Recommandation générale** : identifier le `JSON.parse()` visé (cookie, param d'URL, ou réponse d'API interne) et le rendre défensif contre une valeur vide/absente.

### ISSUE-04 — P1 — Hydratation React cassée sur le calculateur de `/demo`
- **Reproduction** : navigation vers `/demo`, capture console complète — React signale un mismatch serveur/client sur `style={{caret-color:"transparent"}}` pour **tous** les `<input type="range">` et `<input type="number">` du calculateur de coût (Act1 et Act6). "This won't be patched up."
- **Device** : desktop 1440, confirmé en navigateur réel.
- **Impact utilisateur** : l'outil interactif central de la démo (simulateur de coût/ROI) peut avoir un comportement visuel divergent entre le rendu serveur initial et l'état client après hydratation.
- **Recommandation générale** : appliquer le style `caret-color` de façon cohérente entre SSR et client (ex. via une classe CSS plutôt qu'un style inline conditionnel au client).

## Limite d'outillage survenue en cours d'audit

Le serveur MCP Playwright s'est déconnecté au milieu de cette session, sans reconnexion possible. Conséquence directe sur ce registre : les tests de robustesse interactive prévus (double-clic sur le CTA mort d'`ISSUE-02`, retour navigateur après homepage→démo, rafraîchissement d'une page, conservation d'état, viewport Android ~412×915) **n'ont pas pu être exécutés** — ce n'est pas un choix de priorisation ni un manque de temps, mais une indisponibilité pure de l'outillage. Les routes concernées ont été vérifiées uniquement au niveau HTTP (curl : statut, titre, taille de réponse), pas au niveau rendu/JS/interaction. À refaire dans un prochain tour dès que l'outillage navigateur est disponible.
